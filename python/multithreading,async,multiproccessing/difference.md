# Различия многопроцессности, многопоточности, асинхронности
- Многопроцессность использует разные области памяти для каждого процесса и использует несколько процессов. Хорошо подходит для CPU-bound задач. Например для задач где требуется большое количество вычислений каких либо формул/работа с матрицами.

- Многопоточность использует несколько потоков в рамках одного процесса => все потоки работают с одной областью памяти. GIL ограничивает параллельное выполнение кода на уровне байт-кода, но только в CPython интерпретаторе. Для того чтобы не возникало race condition, к общим данным доступ нужно блокировать, например используя threading.Lock, то есть можно выделить участок кода, где нужно быть уверенным в том, что доступ к нему получает только один поток, обернув его в контекстный менеджер with threading.Lock()

- Асинхронность работает в рамках одного потока передавая управление потоком между корутинами с помощью await(в python). То есть корутины выполняются не параллельно, а дают друг другу сигналы через await, что можно выполнять свою задачу. Но важно помнить о том, что синхронные методы не принесут никакого профита при работы с асинхронным кодом, он будет блокировать весь event loop

Асинхронность и многопоточность используют в основном для I/O bound задач. Например для работы с записью чего-либо куда-либо. То есть пока один поток/корутина занята записью другой поток или другая корутина может заниматься другой задачей.
